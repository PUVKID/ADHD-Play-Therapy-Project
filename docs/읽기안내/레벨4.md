## 프로젝트 소개

설계의 핵심은 사용자 특성, 게임 메타데이터, 이전 반응을 분리한 뒤 사례 검색에서 결합하는 것입니다. 추천에 무엇을 사용할지와 추천이 실제로 효과적인지는 다른 설계 문제입니다. 이 원고는 전자의 구성과 후자의 평가 절차를 제안하며 구현 수준의 규격까지 확정하지 않습니다.


<a id="guide-problem"></a>

## 문제와 주요 기능

| 대상·조건 | 동작과 의미 |
| --- | --- |
| 게임 후보·반응 | 정적인 게임 메타데이터와 사용자별 반응을 한 구조에서 연결하면 후보 선정 근거를 추적할 수 있습니다. |
| 사례 구성·활용 | 다만 유사사례를 정의하는 척도, 결측 처리, 사례 갱신 규칙은 실행 가능한 명세로 제공되지 않습니다. |
| 설계와 실증 | 설계의 연결성과 구현의 완결성을 따로 평가해야 합니다. |


<a id="guide-flow"></a>

## 입력·처리·출력

| 자료·처리 경계 | 입력과 출력의 관계 |
| --- | --- |
| 게임 후보·반응 | 사용자 표현과 게임 표현의 결합은 후보 생성과 사례 검색을 매개합니다. |
| 평가 범위 | 이후 평가 결과를 다시 사례로 갱신하는 구조는 피드백 루프가 됩니다. |
| 사례 유사도 | 하지만 유사도 수식이나 배포 서비스가 없으므로 이 연결도를 곧바로 호출 가능한 API 명세로 옮길 수는 없습니다. |

### LEVEL 4 · MMSE·개인 특성·게임 정보가 연결되는 방식

사례 표현, 유사성 평가, 검색, 추천 적용, 성과 평가가 설계상 다른 단계입니다.

MMSE와 게임 정보의 연결은 입력 구조를 설명하지만 특징 가중치·거리 함수·검색 구현을 확정하지 않습니다.

메타데이터 존재만으로 개인화 품질이 검증된 것은 아닙니다.

| 조건·자료 | 의미와 확인 방법 |
| --- | --- |
| <a id="layout18-table-3-row-1"></a> 사례의 구성 | 나이·성별 등 특성,게임 유형·플레이 기록·반응과 인지 성과를 한 사례로 연결하는 제안입니다.실제 환자 기록이나 이용 로그를 제공하는 데이터베이스는 아닙니다. |
| <a id="layout18-table-3-row-2"></a> MMSE 검사 결과와 후보 생성 | 원고 2쪽 시스템 그림은 MMSE라는 검사 결과 정보와 개인 특성을 게임 후보 생성에 연결합니다.<br>검사 점수만으로 ADHD 진단이나 치료 결정을 내리는 구현을 제공하지 않습니다. |
| <a id="layout18-table-3-row-3"></a> 게임 메타데이터 | 메타데이터는 게임 종류와 같은 게임을 설명하는 부가정보입니다.과거 사례와 함께 CBR 추천 모델에 들어가 개인별 후보 선택의 근거가 되는 구조입니다. |
| <a id="layout18-table-3-row-4"></a> 사례 기반 추론 CBR | 과거의 비슷한 사례를 찾아 새 추천에 참고하는 접근입니다.원고 순서는 사례 수집→유사성 평가→사례 검색→추천 적용→결과 평가입니다. |

<a id="semantic-evaluation-level-4"></a>

### LEVEL 4 · 추천 후 평가와 아직 제시되지 않은 성과

평가 설계는 피드백 루프를 제안하지만 사례의 질·선택 편향·추천 적합성을 검증한 구현은 제공하지 않습니다.

부재한 유사도 함수나 효과값을 임의로 정해 설계 제안을 완성된 시스템처럼 설명하지 않습니다.

| 조건·자료 | 의미와 확인 방법 |
| --- | --- |
| <a id="layout18-table-4-row-1"></a> 연구 목표 | 기억력·집중력 훈련 게임 중 개인에게 맞는 후보를 찾고 인지 능력 향상을 돕는 것이 목표입니다.목표를 이미 관측한 개선 성과로 바꾸지 않습니다. |
| <a id="layout18-table-4-row-2"></a> ADHD·대조군 사례 수집 제안 | 환자와 정상 대조군의 특성·게임 반응을 수집하는 절차를 제안합니다.실제 참여자 수·수집 표본·사례 데이터는 제공하지 않습니다. |
| <a id="layout18-table-4-row-3"></a> 추천 이후의 평가 | 이용 반응과 인지 성과를 관찰해 다음 추천에 반영하는 설계입니다.치료 전후 비교·대조군 실험·통계검정을 수행한 효과 검증은 후속 과제입니다. |
| <a id="layout18-table-4-row-4"></a> 구현·결과 부재 | 정량 성능표·구체 유사도 수식·학습 데이터·실행 가능한 추천 서비스는 원고에 없습니다.임의의 계산식이나 임상 수치를 새로 만들어 보완하지 않습니다. |

### LEVEL 4 · 전체 원고를 확인하는 순서와 자료 범위

자료 계층은 논문·미리보기·차수설명·전체구성 안내입니다.

이는 같은 연구를 찾는 여러 경로이며 별도 구현 증거는 아닙니다.

원고의 설계와 저장소 탐색 구조를 분리해 이해해야 합니다.

| 조건·자료 | 의미와 확인 방법 |

## 구조도와 서지를 이 수준에서 해석하기

**모듈 경계 검토:** MMSE 검사결과·개인 특성과 게임 메타데이터가 후보 생성·CBR 모델에 연결됩니다.

이 입력 계보를 사례 수집, 유사성 평가, 사례 검색, 추천 적용, 결과 평가로 분해하면 표현·비교·검색·정책·사후 평가의 경계를 검토할 수 있습니다.

구현되지 않은 스키마·유사도·갱신 규칙을 원고에 있는 설계 결정으로 소급하지 않습니다.

후보 생성과 사례 검색은 기능적으로 구분되지만 실행 인터페이스가 제시된 것은 아닙니다. 추천 이후 반응의 피드백도 설계 연결이며 독립 실증이 아닙니다. 기억력·집중력 향상이라는 목표, 실제 참가자 수·대조군·통계검정 부재, 개인정보 보호와 별도 연구 절차 필요를 동시에 유지합니다.

원고의 저자는 곽윤석·김도연·박정수·안진호이며 2024 한국정보기술학회 추계 종합 학술 대회 논문집 인쇄 쪽 수 1727 –1729입니다.

Korean Institute of Information Technology의 Digital Play Therapy Algorithm for ADHD Adolescent Patients 전체 3쪽을 기준으로 설계와 서 지를 검토합니다.

보관 경로와 출판 연도의 의미는 다릅니다.
