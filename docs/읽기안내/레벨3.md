## 프로젝트 소개

**이 저장소를 재현 자료로 사용할 때는 실행 실험과 원고의 설계 분석을 구분해야 합니다.** 제공물은 전체 학술대회 원고이며 학습 데이터나 실행 가능한 추천 앱은 없습니다. 따라서 먼저 사례 필드와 처리 단계의 대응을 문서에서 확인하는 것이 가능한 작업입니다.


<a id="guide-problem"></a>

## 문제와 주요 기능

| 대상·조건 | 동작과 의미 |
| --- | --- |
| **원고·판본 구분** | 원고를 읽으며 추천 입력 필드, 검색에 필요한 비교 항목, 추천 후 수집할 반응을 별도로 적어 보세요. |
| **입력 범위** | 입력 항목이 있다고 해서 실제 수집 데이터가 있다는 뜻은 아닙니다. |
| **공개 범위** | 공개 원고에 제안된 항목과 제공된 파일의 범위를 먼저 맞춥니다. |


<a id="guide-flow"></a>

## 입력·처리·출력

| 자료·처리 경계 | 입력과 출력의 관계 |
| --- | --- |
| **입력 범위** | 입력·처리·출력 표에서 사용자 특성과 기존 사례가 검색 입력인지, 게임 이용 후 반응이 평가 입력인지 구분합니다. |
| **추천·순위 평가** | 추천 전 자료와 추천 뒤 관측을 한 시점의 입력처럼 섞지 않습니다. |
| **원고·판본 구분** | 실제 원고의 구조도를 따라 각 단계의 입출력을 확인하세요. |


<a id="guide-practice"></a>

## 실험과 사용 흐름

| 확인 단계 | 할 일과 확인 조건 |
| --- | --- |
| **실행 조건** | 실행 재현의 출발점은 제공 파일 확인입니다. |
| **PDF 출력·자료** | PDF로 방법과 도표를 검토할 수 있지만 데이터셋이나 실행 코드가 없어 같은 추천 결과를 계산하는 재실행은 할 수 없습니다. |
| **원고·판본 구분** | 추가 구현을 구상한다면 원고에 없는 유사도와 데이터 조건을 기존 결과처럼 채우지 않습니다. |

## 관측 결과와 해석

| **치료 효과의 근거** | 정확도나 치료 효과 수치를 찾아 채우지 않습니다. |
| **참여자·효과 검증** | 참여자·대조군·전후 평가가 없어 설계의 임상적 우위를 수치로 재현할 수 없습니다. |

## 구현과 핵심 파일

| 구성·역할 | 처리와 확인점 |

| **제공 자료 범위** | 아래 차수 표의 자료 폴더와 상세 설명, 전체 구성을 통해 공개물의 범위를 확인하세요. |

## LEVEL 3 · 조건과 절차를 상세히 읽기


<a id="semantic-cases-level-3"></a>

### LEVEL 3 · MMSE·개인 특성·게임 정보가 연결되는 방식

전체 3쪽 PDF를 열고 2쪽의 입력 항목·유사성 평가·검색·추천·후속 평가를 차례로 대응시키세요.

어떤 데이터를 요구하는 설계인지 기록할 수 있지만 공개 환자 자료나 실행 서비스가 없으므로 새 사용자 추천을 직접 재현했다고 보고할 수 없습니다.

| 조건·자료 | 의미와 확인 방법 |
| --- | --- |
| <a id="layout18-table-3-row-1"></a> 사례의 구성 | 나이·성별 등 특성,게임 유형·플레이 기록·반응과 인지 성과를 한 사례로 연결하는 제안입니다.실제 환자 기록이나 이용 로그를 제공하는 데이터베이스는 아닙니다. |
| <a id="layout18-table-3-row-2"></a> MMSE 검사 결과와 후보 생성 | 원고 2쪽 시스템 그림은 MMSE라는 검사 결과 정보와 개인 특성을 게임 후보 생성에 연결합니다.<br>검사 점수만으로 ADHD 진단이나 치료 결정을 내리는 구현을 제공하지 않습니다. |
| <a id="layout18-table-3-row-3"></a> 게임 메타데이터 | 메타데이터는 게임 종류와 같은 게임을 설명하는 부가정보입니다.과거 사례와 함께 CBR 추천 모델에 들어가 개인별 후보 선택의 근거가 되는 구조입니다. |
| <a id="layout18-table-3-row-4"></a> 사례 기반 추론 CBR | 과거의 비슷한 사례를 찾아 새 추천에 참고하는 접근입니다.원고 순서는 사례 수집→유사성 평가→사례 검색→추천 적용→결과 평가입니다. |

<a id="semantic-evaluation-level-3"></a>

### LEVEL 3 · 추천 후 평가와 아직 제시되지 않은 성과

효과 수치를 찾는다면 정량표·참여자수·전후평가·대조군·통계검정이 실제 있는지 확인하세요.

현재 원고에는 없으므로 미제시로 남깁니다.

실증에는 별도의 개인정보 보호·연구 절차와 실제 사례 수집이 필요합니다.

| 조건·자료 | 의미와 확인 방법 |
| --- | --- |
| <a id="layout18-table-4-row-1"></a> 연구 목표 | 기억력·집중력 훈련 게임 중 개인에게 맞는 후보를 찾고 인지 능력 향상을 돕는 것이 목표입니다.목표를 이미 관측한 개선 성과로 바꾸지 않습니다. |
| <a id="layout18-table-4-row-2"></a> ADHD·대조군 사례 수집 제안 | 환자와 정상 대조군의 특성·게임 반응을 수집하는 절차를 제안합니다.실제 참여자 수·수집 표본·사례 데이터는 제공하지 않습니다. |
| <a id="layout18-table-4-row-3"></a> 추천 이후의 평가 | 이용 반응과 인지 성과를 관찰해 다음 추천에 반영하는 설계입니다.치료 전후 비교·대조군 실험·통계검정을 수행한 효과 검증은 후속 과제입니다. |
| <a id="layout18-table-4-row-4"></a> 구현·결과 부재 | 정량 성능표·구체 유사도 수식·학습 데이터·실행 가능한 추천 서비스는 원고에 없습니다.임의의 계산식이나 임상 수치를 새로 만들어 보완하지 않습니다. |

### LEVEL 3 · 전체 원고를 확인하는 순서와 자료 범위

인용에는 학술대회명·2024·1727–1729·해당 그림 위치를 사용하세요.

실행 요청에는 공개자료가 PDF 중심이라는 범위를 먼저 확인합니다.

성능표나 설치명령이 없는 부분을 새로 만든 명령으로 채우지 않습니다.

## 구조도와 서지를 이 수준에서 해석하기

**원고를 재구성할 때 확인할 항목:** 사용자 측 MMSE 검사결과와 개인 특성, 게임 메타데이터, 후보 생성, CBR 검색을 각각 입력·처리로 구분해 표에 대응합니다.

공개되지 않은 유사도 수식을 채워 넣은 구현은 이 원고 자체의 재실행이 아니라 추가 구현입니다.

추천 뒤 반응을 수집하는 계획과 실제 수집 데이터의 존재를 따로 확인하세요. 원고에는 정량 성능표나 참여자·대조군·통계 검정으로 입증한 임상 효과가 없습니다. 도표를 설명할 수 있는 것과 동일 추천·효과를 계산해 낼 수 있는 것은 다른 재현 범위입니다.
